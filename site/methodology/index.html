How it works

Methodology

The project is intentionally small enough to audit. The data pipeline and dashboard use the same definitions so the numbers shown on the site can be traced back to code.

1. Data checks

The loader requires the operational columns used by the analysis, converts the date field, rejects missing or negative numeric values, and checks that the count of requests completed within SLA never exceeds total completed requests.

2. Performance metrics

Completion rate is completed requests divided by incoming requests. SLA attainment is requests completed within SLA divided by completed requests. Quality rate is one minus quality errors divided by completed requests. Productivity is completed requests divided by available staff.

3. Demand spike detection

For each region and user profile, the pipeline compares incoming demand with a rolling 28-day mean and standard deviation. A day is flagged when its absolute z-score is at least 2.5. The rule is transparent and easy to inspect.

4. Forecast

The baseline model is a linear regression with a time trend plus sine and cosine features for weekly seasonality. The forecast is clipped at zero because negative request volume does not make operational sense.

Why a simple model?
The goal is not to claim that linear regression is the best possible forecasting method. It gives a baseline that can be explained, challenged, and compared with stronger models later.

5. Staffing estimate

Recent productivity is calculated from the latest 28 days of completed requests and available staff. Forecast demand is divided by that productivity rate and an 85 percent utilization target, then rounded up to produce required staff. The staffing gap is required staff minus recent typical available staff.

6. Reporting layer

The pipeline writes daily metrics, regional summaries, anomaly rows, staffing forecasts, and a combined actual/forecast timeline. Those files can feed Excel or Power BI, while the web dashboard uses a smaller JSON summary generated from the same outputs.

Reproduce it

python -m pip install -r requirements.txt
python src/generate_sample_data.py
python src/pipeline.py
python src/build_dashboard_data.py
pytest -q
Every number on the dashboard comes from code in the repository.
